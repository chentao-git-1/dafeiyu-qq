# 统一私聊上下文与按需语义召回

本模块是严格改造方案 S1–S3 的基础路径，默认 `shadow`。它不会自动进入正式聊天，也没有新增学习任务、主动联系或公开发布。S4–S7 仍需前序评测和灰度支持后实施。

- `off`：关闭资料采样并隐藏本模块工具。
- `shadow`：保留原有请求、历史、附件和回复逻辑，只读取现有存储，保存不含正文的内存数值样本；不调用额外模型。
- `active`：只有 `active_private_users` 中且通过原有真实身份、白名单校验的私聊使用新路径。群聊、定时合成事件和其他账号不启用。

0.2.0 要求自然相处模块提供 `dialogue_context_protocol=2`（候选 0.8.0）。旧版 0.7.3 以及上一版协议均不能启用新路径；状态显示 `legacy_adapter_ready=false`。

活动路径保留原生会话历史和工具集合。自然相处模块会跳过表达分类、删问句、短回应裁剪与哈希台词；当前事实、承诺、任务、发送回执和最终交付记录继续使用现有保护。基础人格、群聊插件与调度政策尚未全部收敛，不应声称整个架构已经完成。

相关记忆按完整条目预算注入；明确需要旧细节时，主模型可选择 `dafeiyu_recall`。该工具使用当前会话原有提供商在不带工具的请求中选择证据编号，最多 40 条已授权候选、最多返回 5 条；没有匹配可返回空。它不是全文历史搜索。

0.2.0 的 active 路径在普通回复及 `send_message_to_user` 的文本发送前增加语义核对。模型给出原文中的问题片段和完整修订；代码验证编号、逐字出处、结构及来源是否仍有效。原样通过不再检查，发生修订才独立检查修改后的事实；失败或超时不发送未核验草稿。工具检查失败会清空本次发送内容，因为框架捕获钩子异常后仍可能执行工具。媒体与目标顺序在成功修订时保持原样。

`response_review=enforce` 为候选默认；`audit` 仅观察，`off` 供离线对照。影子模式始终没有新增模型请求。活动模式每轮最多两次核对，每次修订最多追加一次事实检查，即最多四次辅助请求；各请求不带工具、不重试，不执行额外外部动作。这是候选质量保护的成本折衷，尚未达到原方案普通闲聊多数一次生成与综合成本目标。

`verified_self` 分开记录已验证的完成作品与当天十分钟内真实启动的任务；缺少或过期记录不证明有项目正在进行。角色偏好、虚构小屋与作品记录分别提供。仅对唯一匹配的已知操作员人格做模板迁移，保留身份、权限、工具及其他插件规则；不识别或有歧义的人格保持原样。没有按用户用词选择固定回复。

每次检索先核对共享或同人同会话范围，模型返回只能引用提供过的编号；等待结束后再次读取存储，过滤期间被删除、更正或撤回的记录。不缓存原文。旧库缺失／异常时记录来源不可用，不创建、迁移、清理或更改它。

长期记忆的 `MemoryRetriever` 同时修复无关条目仅凭重要度入选的问题。可选嵌入接口已连接 AstrBot `get_embedding`，仍默认关闭；最多增强 16 条已经可见的候选，缓存仅保留内容摘要和向量，30 分钟失效。没有配置嵌入提供商时，按需语义召回仍可使用当前聊天模型。

状态接口 `/plugins/extensions/dafeiyu_dialogue/status` 仅输出模式、数量、长度和辅助请求／缓存／拒绝／耗时／提供商回报的 token 数值，不输出账号、正文或提示词。样本为当前进程内最近 200 条，重载会清空；不是多日持久化自然度报告。

开发验证：`python scripts/run_tests.py test_semantic_dialogue.py`。完整项目入口包含旧版 197 项和新的边界测试。`tests/dialogue_scenarios.py` 提供 80 组六轮情境，48 组开发、32 组隐藏；真实模型输出必须人工比较，不能将“未抛异常”认定为自然度通过。

第二阶段完整回归 240 项通过，但真实模型仍会漏过泛泛邀请、整改说明，并出现核对失败的保守回复；保持影子模式。详细结果见 `docs/SEMANTIC_DIALOGUE_STAGE2.md`。
