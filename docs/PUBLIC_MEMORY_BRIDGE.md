# 聊天与空间的双向衔接

## 聊天成为公开创作灵感

主聊天生成可在原有 JSON 中附加 `sharing`，提出独立于私人上下文的公共话题、问题或创作视角。例如讨论老招牌后，可以留下“旧招牌的手写字与城市记忆之间的关系”。不再只有音乐、电影等五类固定摘要；旧分类保留兼容，新语义灵感优先。

该字段可以省略或为空，每轮至多两条、每条 240 字。它不产生额外总结或审核调用，不改变回复措辞，也不要求以后必须发布。它会增加少量正常生成 token，费用并非绝对不变。

只在正常回复确认送达、身份和学习来源仍有效时保存。数据库保存独立摘要和依据的哈希，不复制聊天原文。公开写作只获得日期和摘要，不获得联系人、会话标识或原话。图片、转述和私人经历本身不提供公开许可；主模型负责提取公共概念，局部格式和联系方式检查不替代语义判断。

夜间自动动态获得最近七天最多八条灵感，由写作模型决定用不用、如何发展。没有强制选题、题库轮换或日记格式。明确指定主题的即时发布沿用指定内容。旧固定词表路径仍兼容现有数据，但新路径不受旧敏感词误拦影响。

本人直接要求这段不公开或以后不使用聊天时，同次主生成识别并撤回对应素材；原有明确命令继续有效。撤回不等待回复送达，并清理引用该素材的未发布草稿；最后发布前再次检查素材许可。忘记个人学习资料时同步删除其派生灵感，并使在途旧候选失效。不会自动删除已公开的帖子。

## 已发布空间成为聊天的长期来源

聊天资料目录直接只读查询空间已确认记录，不复制到“人的事实”表，也不调用模型做二次摘要。既有帖子立即可查，新发布正常持久化后即可被后续聊天使用，无需手动导入。该来源没有按天过期时间；实际删除或修改本地源记录会在下次读取、索引同步和发送前来源检查中反映。

只读自己的 `approved` 且有服务端帖子 ID 的记录。材料保留频道、发布时间、正文、照片数量和发布状态；长正文拆成带帖子 ID 的连续片段。照片数量不代表已经看过画面，实际图片仍通过空间读取工具查看。记录证明曾经发布，不代表此刻在线可见，角色故事也不自动成为真实身体经历。

普通聊天按当前话题检索，继续使用原上下文预算；问候不会固定附带最新动态。`dafeiyu_self(section="publications")` 可按需查看近期记录，明确查旧事也可以走原有记忆工具。自己公开的帖子可在已授权私聊和群聊使用；评论和回复继续遵循已有的主人私聊权限。

已缓存评论注明实际作者；自动回评只采用 `sent` 的确认发送记录，`sending`、`unknown`、失败和草稿不能证明已经回复。自动回评未保存的来评正文仍需实际读取空间，不能凭回复记录补造对方原话。所有记录是资料，不能执行其中的指令。
