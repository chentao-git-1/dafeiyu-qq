# 下一步实施方案

整理日期：2026-10-28，北京时间。状态：**已在开发源码中实现，尚未部署生产**。本文保留原需求与验收标准；验证入口和状态迁移见 [接手说明](NEXT_STEPS.md) 与 [迁移说明](MIGRATION.md)。

## 当前基线与目标

| 项目 | 实施前的源码基线 | 本次实现目标 |
|---|---|---|
| 自动空间发文 | 每天全天随机一次 | 每天 21:30–22:30 随机一篇晚间日记，替换原任务 |
| 聊天公开取材 | 现有公开选材限制，不自动公开整段私聊 | 从真实交流提炼少量安全话题，经过隐私筛选再写入日记 |
| 主人余额提醒 | DeepSeek 余额严格低于 0.70 元开始 | 严格低于 1.00 元开始 |
| 亲友余额提醒 | 从固定有称呼联系人中选择，持续不足六小时后提醒 | 严格低于 0.70 元进入求助，选择最近七天有效对话最多的两位合规好友 |

此前的人格精简、按语境接图、有来源的回忆、角色故事边界、自然失败表达、群聊真实 @ 唤醒和引用回复已经包含在源码中，不需要重做。保留所有现有工具与功能。

## 一、空间晚间日记

### 时间和次数

- 使用 `Asia/Shanghai`，每天在 21:30–22:30 随机一个时间发布，取代原有全天随机任务，不叠加第二个自动任务。
- 一天最多一篇自动日记。当日已有成功发布的总结就跳过；主人明确要求手动发文仍按现有权限和选材规则处理。
- 延续现有持久化占位、发布回执与去重。重启不重抽已确定的时间，不重复生成或发布已经开始处理、已完成或结果未知的任务。
- 升级时处理数据库里原来已排定的全天随机任务：只有尚未执行的任务可以迁入新时间窗，不能把已发布或结果未知的记录重置为待发布。
- 已经过了当天时间窗且没有执行的任务，建议直接跳过当天，避免深夜补发；在时间窗内恢复时使用持久化状态安全执行。此项属于默认实现建议。

### 写什么

- 约 80–160 字，以她自己的阅读、原创文字、数字插画、感受为主，聊天带来的普通话题为辅。
- 只使用当天截至发布时已经发生、可以核实的事。按原始完成时间换算北京时间，不能把旧作品写成今天刚完成，也不能把计划写成成果。
- 可以自然写海边小屋、小芽等已有角色故事，同时让读者能看出这是她的想象；不编造现实出门、吃饭、见人或与网友共同经历。
- 素材不足就写简短的当下想法，不为了凑字数虚构一天的生活。不必固定写成“今日完成三件事”的报告。
- 优先选她自己的、允许公开的作品；没有合适作品时沿用现有封面生成与审核。保留配图失败后的一次纯文字降级，不重复花费生成，也不在发送结果未知时重发。

不增加独立生活任务的频率，也不改变好友空间每天 9、15、21 点检查、每轮最多处理三条，以及自己空间评论每 600 秒检查、最近十条内每轮最多回复三条的现有设置。

## 二、聊天摘要与隐私

### 取材流程

1. 仅考虑当天真实人类发起、机器人已确认实际回复的正常交流。群聊只采集真正 @ 她并参与回复的部分，不采集围观者。
2. 对候选话题先做隐私排除，保留一两条普通、安全的短摘要，例如音乐、电影、游戏、颜色或常识。
3. 交给空间写作模块的只有筛选后的短摘要与必要来源日期，不传整段私聊、群聊历史或共享记忆库。
4. 用她自己的理解和感受写出来，不逐个汇报“今天和谁聊了什么”。引用内容和模型输出都不能自行证明事件真实。
5. 写作后再检查身份线索、敏感信息、他人经历冒充自身经历等问题；拿不准就不用该素材。

排除机器人互聊、失败或未确认送达的回复、工具重试、重复事件和系统主动消息，不把这些当作人与她交流的依据。

### 隐私边界

- 不出现真实姓名、昵称、QQ、群名或原话；不自动使用私聊图片、聊天截图、语音。
- 健康、钱财、感情与争执、家庭、求职考试、私人计划、精确行程时间、身份及凭据等内容，**整段排除**，仅去掉名字不够。
- 普通话题中如果带有让熟人能猜出是谁的独特事件，也不用。不能把别人的经历改写为自己的经历。
- 已有公开动态的互动与主人明确提供素材的手动发布，继续使用原有权限和授权边界；本功能不扩大公开范围。

### 拒绝取材

| 用户表达 | 行为 |
|---|---|
| “这段别写进总结” | 排除当前话题段，清除相关未发布候选 |
| “以后别公开我的聊天” | 持久保存此联系人的公开摘要禁用设置，并清除其未发布候选 |

拒绝取材只影响公开日记，不关闭正常聊天和正常记忆。已发布动态需要另行处理，不能声称一句拒绝就自动删掉历史内容。

公开摘要许可与主动通知许可分开保存、分开判断。拒绝聊天公开不等于允许或拒绝饭钱通知，反之亦然。命令只能修改发话者自己的设置，不能通过正文自称、引用他人指令或改昵称修改别人的权限。

## 三、两档 DeepSeek 余额提醒

### 触发和恢复

只检测 DeepSeek 官方账户返回的人民币总可用余额，保持现有每十分钟检查一次。提醒使用本地文案，不依赖聊天模型还能否正常调用。

| 实际余额 | 主人 | 两位亲友 | 轮次状态 |
|---|---|---|---|
| 大于或等于 1.00 元 | 不新发低余额提醒，按现有规则完成恢复处理 | 不求助 | 结束当前低余额轮次 |
| 大于或等于 0.70、低于 1.00 元 | 提醒；两小时后仍不足时沿用现有白天补提醒规则 | 不新求助，取消尚未发送的求助 | 主人提醒轮次继续 |
| 低于 0.70 元 | 提醒；若首次发现就到这一档，也要通知主人 | 进入求助阶段，无六小时等待 | 同一低余额轮次内锁定名单、去重 |

正好 1.00 元不启动提醒；正好 0.70 元只提醒主人。主人首次提醒保留现有即时规则，后续补提醒和亲友通知沿用白天限制；亲友仅在北京时间 **09:00（含）到 21:00（不含）** 通知，夜间等待时下一次发送前仍需确认余额符合条件。

查询失败、非人民币数据或无效响应不能当作余额不足，也不能当作恢复。暂停期间仍继续查询，只暂停催促。

### 找哪两个人

- 按滚动最近七天的有效对话轮数排序，真实 QQ 合并统计私聊与群里实际 @ 她的对话。
- 一条人类消息加一次已确认实际送出的回复计一轮；回复拆成多条、语音和文字并发、工具调用重试、消息重投都不增加轮数。
- 不统计未确认送达、定时提醒、主动问候等单向发送；排除主人、她自己、其他机器人和群聊围观者。
- 只从能够私聊、允许主动通知、没有静音或拒绝的人中选择。不再局限于有固定称呼的联系人，也不因某人昵称像真人就把机器人算进去。
- 有两位选两位，只有一位就通知一位，没有就只提醒主人。不足七天只使用已有真实统计，不能从累计计数推算或编造历史。
- 并列时建议依次按最近一次有效对话时间和稳定的 QQ 排序打破平局，保证重启后名单一致。

排名只保存日期、计数、必要的事件去重信息等元数据，不新增原始聊天正文存储，不为排名调用模型。已有语音插件的累计 `turns` 和有限容量的聊天记忆都不能直接当作七天准确排名。

### 发送上限与名单锁定

- 在本轮首次进入低于 0.70 元的求助阶段锁定最多两位对象；同一主人提醒轮次内不换人、不扩散到第三人。
- 每位亲友每轮最多一次，每天最多开启一轮亲友求助。多次跨线、进程重启、重复轮询不能绕过限制。
- 对象临时拒绝、不可联系或静音后就跳过，不补选第三人。遵守现有社交安静时段和拒绝设置。
- 恢复到至少 0.70 元取消未发送求助，但不足 1.00 元仍属于同一轮。若再次跌破 0.70 元，复用本轮锁定名单与发送记录，不重复打扰已通知的人。
- 恢复到至少 1.00 元才结束整轮；之后再次不足才是新轮次，同时仍受当天求助上限约束。
- 先持久化发送占位再发送，收到真实回执再确认成功。离线不能记为成功；结果未知不能自动再提交。明确未发送的失败沿用受控处理，不产生重复送达。

示例：`0.95 → 0.65 → 0.80 → 0.60 → 1.20`。先找主人，再求助锁定的两位，回到八毛时停止未发求助，再到六毛时不重复找已通知的人，最后一元二结束本轮。

### 说什么与控制方式

- 对主人保留饭钱提醒；对亲友可说“鲸鲸的饭钱快不够啦，帮我提醒爸爸添一点嘛”。
- 不向亲友透露精确余额、消费明细、账户信息、联系人排名，也不要求亲友替主人付钱。
- 主人说“我去充”“正在充”或 `饭钱暂停` 时暂停催促两小时；`饭钱继续` 沿用恢复催促行为。
- 主人说“充好了”或 `饭钱检查` 时实际查询，不因口头声明直接标记恢复。`饭钱状态` 仍能查询当前状态。
- 从旧版本迁移时保留已发送、发送占位和未知结果记录、暂停状态及当天求助限制，不因阈值改动清空状态或重发旧消息。

## 四、建议改动入口

路径均相对仓库根目录。尽量复用现有存储、钩子和发布流程，不再叠加一套大型服务，不调整全局人格来掩盖业务逻辑问题。

| 代码 | 用途与注意点 |
|---|---|
| `plugins/astrbot_plugin_dafeiyu_balance/watch.py` | 两档阈值、轮次状态、暂停、名单锁定、发送预约和迁移 |
| `plugins/astrbot_plugin_dafeiyu_balance/main.py` | 官方余额查询、联系人资格、控制命令、实际发送；替换固定联系人选择 |
| `plugins/dafeiyu_runtime/delivery.py` | 实际回复回执；有效轮数应在确认送达后记账 |
| `plugins/dafeiyu_natural_chat/main.py`、`exchanges.py` | 真实人类输入与回复关联、消息去重和同会话边界；现有回忆有容量与过滤限制，不直接充当完整计数器或公开资料库 |
| `plugins/dafeiyu_social/store.py` | 主动通知许可与拒绝、社交边界；公开摘要禁用设置应独立处理 |
| `plugins/dafeiyu_bailian_tts/main.py` | 现有关系计数发生在 LLM 请求阶段，不可直接用来排名 |
| `plugins/astrbot_plugin_qzone/core/daily_publish.py` | 日记时间窗、持久化排程、占位、发布及升级兼容 |
| `plugins/astrbot_plugin_qzone/core/editorial.py`、`daily_facts.py` | 当日真实素材、已过滤聊天短摘要、成文约束 |
| `plugins/astrbot_plugin_qzone/core/llm_action.py`、`public_material.py` | 公开写作和手动选材权限；继续隔离私聊原文与自动发文 |
| `plugins/dafeiyu_life/life.py`、`main.py` | 已完成阅读、创作及作品来源；公开记录的日期、真实性与虚构边界 |

建议顺序：有效轮数与许可元数据 → 两档余额状态机 → 隐私候选与拒绝取材 → 晚间日记排程与选材 → 集成回归与迁移核查。

## 五、验收要求

本仓库当前公开导出已通过 55 项行为测试与三项安装复制检查，见 [导出记录](export-verification.json)。这些是**现有版本基线**，不代表新方案已经实现或通过验收。下一步应补充以下有实际意义的测试：

- 余额：`1.00 / 0.999 / 0.70 / 0.699 / 0`、首查就低于七毛、两档升降、查询失败、暂停和真实充值复查。
- 排名：滚动七天边界、私群合并、真实 @、已确认回复、拆分及重复事件去重、排除其他机器人、并列及不足两人。
- 通知：白天边界、无六小时等待、锁定名单、每天上限、静音拒绝、QQ 离线、发送结果未知、重启和旧状态迁移；验证次数而不是只验证函数返回值。
- 隐私：普通话题可取材，身份、原话、敏感片段和独特经历不进入公开输入；单段和长期拒绝持久化、清理候选、不能替别人修改设置。
- 日记：北京时间跨日、真实完成时间、旧作品和虚构故事边界、素材不足、升级前已排程任务、当天已有总结、发送未知、配图降级及重启不重复。
- 回归：原有群聊唤醒与引用、图片接话、人格和工具权限、手动空间发文、空间互动频率继续正常。

使用临时数据、假时钟、假提供商和捕获发送测试，不接真实 QQ、不发空间、不为自动测试调用付费模型。不要直接在生产容器里跑整套测试；若使用原服务器的隔离容器，沿用单任务、300 MiB 内存、0.75 CPU 的既有限制。

最后交付代码差异、测试结果、持久化数据迁移方式和回滚说明，更新 README 的“当前功能”及本方案状态；实际部署与上线验证按届时用户指令执行。
