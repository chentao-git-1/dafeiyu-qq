# 可变化的兴趣与行程恢复

手帐仍可以是鲸鲸喜欢的东西，但初始兴趣不再进入每次聊天、社会互动和选题的默认材料。身份画像保留名字、语气与判断方式；初始兴趣标记为可变化的起点，按需查询，不用禁词、固定轮换或指定新话题控制表达。原作品、项目和成长记录保持。

普通聊天不再自动携带全局项目反思，当前人的持续交流偏好仍在其私聊范围内保留。`dafeiyu_self` 的 `thoughts` 留空 `query` 只读当前意向；讨论具体旧项目时填写问题，使用本地相关性检索读取项目与可核验反思。暂停的兴趣也可查询。`interests` 返回初始兴趣的性质与项目状态目录，具体成长倾向同样按查询相关性读取，无额外检索模型。

规划和自主选题只收到项目目录、实际活动分布与作品索引，不再收到每个项目的完整旧问题、作品正文和反思。选定项目后，执行阶段仍取得该项目的相关反思与实际选用的来源。新兴趣不要求先引用旧材料，模型也可以继续原兴趣、暂停或休息。

夜间计划新增可选的顶层 `project_updates`：模型选择 `active` 或 `paused`，引用真实项目编号与版本。安排暂停项目需要明确恢复，不能在同一计划中一边暂停一边执行。项目状态和整份计划通过 SQLite 跨文件事务一起落库；版本变化或活动写入失败时一起回滚。部署前确认两个数据库均使用 DELETE 回滚日志；已有活动运行时仍读最新版本。

11 月 7 日的线上检查发现，行程模型沿用了聊天配置的 `max_tokens=512`，而失败行只有 `JSONDecodeError`，没有保存完整响应，无法事后确认昨晚具体的截断位置。本次将 **agenda 请求的输出上限设为 4096**，在 AstrBot 合并 `custom_extra_body` 后按请求覆盖，普通聊天原配置不变；用真实适配器和模拟 HTTP 客户端验证并发隔离、作用域复位和卸载恢复。上限不等于每次实际使用量。

完整且无歧义的 JSON 包装问题在本地解析；被截断、冲突或缺字段的响应不补造为计划。`finish_reason=length` 明确判为失败。失败诊断写入私有 `day_plan_attempts`，对外状态不返回原文。正常日期仍一次规划；明确输出失败最多再尝试一次，至少间隔一小时，且该日期没有任何已保存活动、仍有可用时间。未知中断或传输超时不自动重试，避免对结果不明的调用重复收费。旧失败行保留为第一次历史记录。

白天恢复只允许当前剩余窗口，保存时再次核对时间。不会补跑上午、覆盖既有作品、重发空间或修改 QQ 权限。人物设定只替换本项目拥有的生活段落，不改其他人格字段。

验证采用临时数据库、模拟模型和传输。新增回归覆盖旧反思相关性、暂停兴趣查询、选中项目的详细材料、计划与项目事务回滚、旧失败迁移、有限重试、截断拒绝及真实 AstrBot 请求预算。正式部署后的当天行程恢复属于用户请求的正常运行，单独记录，不当作模型测试。
