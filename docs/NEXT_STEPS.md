## 新电脑开始

安装 Git 和 Python 3.12，然后在打算保存项目的位置执行：

```powershell
git clone https://github.com/chentao-git-1/dafeiyu-qq.git
cd dafeiyu-qq
git status --short
git switch -c codex/evening-diary-balance
```

如果已经克隆过，在确认没有未保存改动后切回 `main` 并执行 `git pull --ff-only`，再创建工作分支。在 Codex 中打开克隆出来的 `dafeiyu-qq` 文件夹，先阅读本文件和 [完整方案](PLAN.md)。

可以先运行不依赖完整框架的纯行为测试：

```powershell
py -3.12 tests/test_persona_tuning.py plugins
```

需要执行完整的现有隔离测试时，在仓库根目录建立虚拟环境，安装依赖后运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r framework/requirements.txt -r plugins/astrbot_plugin_qzone/requirements.txt -r plugins/astrbot_plugin_dafeiyu_draw/requirements.txt
.\.venv\Scripts\python.exe scripts/run_tests.py
```

完整框架依赖较多，安装过程需要网络。`scripts/run_tests.py` 使用临时数据和假提供商，不需要配置生产账号，也不启动真实机器人；遇到本机依赖安装问题应如实记录，不要因此拿生产账号替代测试。框架正式运行方式以 `framework/README_zh.md` 为准。

## 接手时优先处理的坑

1. 排名要用已确认送达的有效对话轮数。语音插件现有 `turns` 是累计请求计数，不是最近七天有效交流；有容量限制的回忆库也不能提供准确全量统计。
2. 把余额分为一元和七毛两档后，恢复八毛只能取消未发亲友求助，不能结束主人提醒轮次。结束整轮要到至少一元，跨线和重启不能重复通知。
3. 求助名单在进入七毛阶段时锁定，不从“有名字”的列表随机选，也不在同一轮中换第三个人。一次最多两人、每天最多一轮，遵守主动通知许可。
4. 空间日记替换原自动任务，同时兼容已保存的排程。已发布、执行中或结果未知的任务不能重置；好友空间检查频率不变。
5. 聊天摘要要先筛隐私再送入公开写作，不是把整段私聊交给模型并要求“注意隐私”。拒绝公开与拒绝主动通知是两个不同设置。
6. 本次仓库是去除私人标识的源码，不包含生产运行配置、登录态和聊天数据库；不要用示例 QQ 直接部署原机器人。

实现入口、阈值细节、文案例子及测试清单都在 [PLAN.md](PLAN.md)。优先修改相关插件，保留现有工具，不做无关的大重构。

## 如需连接原服务器

服务器地址、登录凭据、DeepSeek 等提供商密钥、QQ/空间登录态和真实身份映射不在这个公开仓库。需要时通过你自己的私人方式转移，保持在仓库外；无需把聊天数据库带到开发电脑才能写代码和运行上述测试。

`identities.example.json` 左侧是源码中的示例号码，右侧在仓库外的私人文件里替换成实际号码。安装脚本复制到独立运行目录时才应用映射，不改公共源码，也不会覆盖已有插件。已运行服务的升级应备份相关插件与状态，使用经审查的差异和兼容迁移；不要直接把示例源码覆盖到生产目录。

上线前核对生产版本是否在本次快照之后又发生变化。人格或界面里显示“开启了新功能”不能作为生效依据，应核对实际加载版本、持久化状态和受控验证结果。
