# 夜间规划与白天行程

2026-11-06：核心 0.3.0、日常 0.7.0、统一对话 0.7.1。部署结果核验后记录。

用户选择北京时间 23:00 规划、次日 09:00–21:00 执行；活动数量交给模型决定。夜间启用后，周期性的旧打算评估由一次次日规划替代。模型自行选择阅读、写作、服务可用时的绘画，决定时间和条数，也可以安排休息或返回空计划。没有每天一项或三项的固定配额，也不再沿用旧模式每七项才可绘画的轮换限制。

正常路径每个目标日期只请求一次规划模型，白天复用保存的选择，不再为每一项额外调用选题模型。原有余额有效性与最低余额检查继续执行；阅读、图像服务按实际需要调用。内容格式修复和阅读失败后的一次文字替代沿用原有机制，不重复搜索或生图。请求数和 token 用量计入统一对话的 agenda／activity 后台统计。

## 持久化与执行

- 新模式在原 `life.db` 中增加计划、活动和逐项失败表，旧每日运行表与作品保持可读。首次启用从次日开始，不在白天安装时额外塞入当天活动。
- 计划先持久化预留，再发模型请求。失败或中断有明确状态，重启不会重复收费生成同一天的计划。错过夜间且从未尝试规划时，可在次日执行窗口结束前补建剩余时段的安排。
- 每项活动具有独立编号、执行状态和作品文件。同一天可以完成多项，实际完成记录继续用于回忆、成长和当天空间素材。
- 09:00 前与 21:00 后不启动新活动，过期条目不跨日补跑。到点检查采用分钟轮询；已经开始的活动可完成当前操作。
- 执行时读取项目最新版本；项目已暂停、结束或选用材料已撤回时，条目不会强行恢复旧状态。模型在作品反思中暂停项目后，后续关联条目也会据实跳过。
- 余额不足时等待，恢复且仍在窗口内才推进。中断且结果不明的条目不会自动重做；一个条目的失败或中断不阻塞后面的安排。
- 阅读失败后的替代写作只处理同一条目。失败记录独立保留并带活动归属，后续成功不会覆盖错误，也不会混淆同一天不同条目的结果。

所有活动都是机器人自己的数字活动。聊天照常，QQ 主动消息与空间原有排程保持独立，没有因为行程新增发送权限或安排现实身体经历。

## 查询与配置

模型可通过 `jingjing_life(action="agenda")` 或 `dafeiyu_self(section="agenda")` 只读查询今天、明天的安排及实际状态，不触发规划、执行或发送。未生成的明日计划明确返回 `not_planned`，不能以当前意向补成已经保存的行程。

`dafeiyu_life` 配置新增 `nightly_agenda=true`、`planning_hour=23`、`execution_start_hour=9`、`execution_end_hour=21`。条数不设配置配额。关闭新模式才回到旧的单次日常机制；保留的数据不会被删掉。
