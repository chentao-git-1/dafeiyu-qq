# 第二轮实施：有依据的自我状态与发送前语义核对

2026-10-30。基于 `eb7e12441711a3db2d92c3e598f52f5265207b9c` 继续同一草稿分支。对应第一轮失败的自我经历编造、泛泛邀请与表达反馈问题，继续完善原方案 S1–S3；不代表 S4–S7 的学习、反思、活动规划与主动策略已经完成。

## 实际改动

- `dafeiyu_dialogue` 0.2.0 的 `verified_self` 将已验证完成作品、当天十分钟内真实启动的活动和未知状态分开。读取原库，不创建或迁移数据，不把聊天中自己的说法当作活动证明。
- 角色偏好、虚构小屋设定与实际活动分开供给。明确的故事可以新写、续写，代码、台词、引用不按现实行动拦截；具体旧剧情仍须有来源。
- 仅对唯一匹配的已知操作员人格迁移已有表达段落，保留身份、工具、权限和外部插件规则；未知或匹配有歧义的人格原样保留。未实现所有提示收敛到八百字的目标。
- 普通回复及 `send_message_to_user` 的文本组件先作语义核对。模型逐字指出有问题的片段并给完整修订；代码检查结构、编号、出处、范围和预算。原样通过不改字，必要追问与技术内容保留，不按用户关键词挑回复模板。
- 修订后独立检查新文字的事实，避免把“正在弄”改成仍然没有依据的“还没弄完”。错误、超时、检查不通过或预算耗尽时不发送该草稿；发送工具的参数会清空，避免框架吞掉异常后仍继续发送。
- 等待模型后再次读取活动与已用记忆，删除、更正或来源变化则不沿用旧材料。同一轮相同草稿与材料复用结果，不跨轮缓存原文。记忆适配层和合成器都执行可见性检查。
- 辅助请求只使用本会话原提供商，不带工具、不重试。每轮最多两次核对，每次发生修订才追加一次独立检查，最多四次辅助请求；分别记录核对、复核、召回的请求、耗时和提供商回报的 token。影子模式没有这些新增调用。

自然相处候选升级为 0.8.0，提供协议 2。生产旧版 0.7.3 及上一版协议都不能误启用该新路径。原身份、发送、配额、任务与事实保护保留；仍有旧事实文案保护，尚未完成“所有自由文本只经一个出口”的收敛。

## 验证与实际失败

本地及生产镜像中断网运行完整入口均为 **240 项通过**，其中语义对话组 43 项。测试使用临时库、假提供商和捕获发送，覆盖影子不变、权限范围、取消／超时、发送工具绕行、修订后二次检查、原生历史与确认送达记录一致、必要追问、活动过期、读取不写库以及等待时遗忘。

现有 `deepseek-flash` 共执行 **280 次**真实 API 请求：144 次主生成、120 次核对、16 次修订复核。所有输入均为合成资料，没有真实 QQ 发送或生产记忆写入。开发中保留全部失败记录；最终冻结版本再执行两组隐藏情境，各重复两次，未根据隐藏输出调整代码或提示。只覆盖 32 组隐藏材料中的两组，没有人工盲评。

最终候选连续对话共 48 轮：38 轮原样通过、8 轮修订通过、2 轮核对不通过而阻止发送草稿。另有 12 个草稿探针，其接受／修订决策均符合预期，但其中一份修订仍保留无依据的未完成手帐，独立检查将它拦下。这不是“12 项自然度全部通过”。

已确认的改善是：上一轮的无依据手帐／未完成画作能被发现并拦截；必要排查问题、原样代码、台词分析和明确虚构续写能保留。仍未解决的失败包括：泛泛邀请和整改说明有时被判为可接受；修订可能继续塞入服务邀请；过于保守的事实检查会打断交流。技术排查内容也存在过度肯定，不能以保留问句代替整体正确性评估。

## 部署边界和后续条件

北京时间 01:37 已核实新观察模块升级到 0.2.0，维持 `shadow` 与空的活动联系人列表，辅助调用计数为空；自然相处仍为 0.7.3，候选 0.8.0 和其他业务修改未热更新到生产。原业务源码和配置摘要一致，容器未重启且健康，发送／群策略／确认送达守护均有效。安装前完成私有代码／配置及 SQLite 一致备份；观察器自身可以补入新增配置默认值，原业务配置不变，不以旧库覆盖新数据回滚。

结论为 **质量门槛未通过，禁止自动推广活动路径**。下一步先解决核对漏过与过度保守的矛盾、同步调用成本，补全召回与连续对话的独立评测；之后才能按原方案做主人私聊灰度、最短观察期和有效样本量验证。S4–S7 的事件学习、自我反思、持续项目及主动内容选择继续保留为未完成项，不能用更多固定台词代替。
