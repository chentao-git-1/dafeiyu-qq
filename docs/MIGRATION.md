# 状态迁移与回滚

本次代码不自动部署。上线时先比对实际运行版本，保留生产在源码快照之后的改动；真实映射、配置和备份均留在仓库外。

## 升级前

停止相关后台任务或停机器人，再备份本次修改的插件、余额 `state.json`、社交 `preferences.db`、空间 `posts_5.db`、生活 `life.db` 与作品目录。SQLite 备份须一致取得：停服务后复制，或使用 SQLite backup API，不能遗漏活动 WAL。

在独立目录应用真实身份映射并审查生产差异。`install_plugins.py` 不覆盖已有插件，不用于直接就地升级。新文件 `dafeiyu_social/activity.py` 与 `astrbot_plugin_qzone/core/diary.py` 必须随插件复制。在隔离环境执行 `python scripts/run_tests.py`。

## 自动迁移行为

- **余额**：首次加载把状态版本 1 转为 2，先在同目录保存权限 0600 的 `state.v1.bak`，不覆盖已有备份。保留回执、发送占位、未知结果、暂停和当天求助限制；重启时发送中转为未知。已尝试求助的旧轮次保留名单，尚未求助的轮次在七毛阶段按新排名锁定。
- **对话与公开许可**：在原 `preferences.db` 增加独立表，不改语音、主动消息或安静时段。统计从新确认的回复开始，不导入旧聊天或累计请求数。滚动七天按时间戳计算，依次按有效轮数、最近一次交流、稳定 QQ 排序。
- **日记**：在原 `daily_publish_runs` 增加 `policy_version`，复用同一个任务 ID。只迁移 `scheduled` 行；`generating`、`publishing`、`published`、`unknown` 等记录不重置。时间窗已过就跳过当天；窗口内恢复可继续尚未开始的任务，不重抽已保存的有效时间。
- **作品**：只读原完成记录和作品，以实际完成时间、路径和 SHA-256 核验当天素材，不增加独立生活任务频率。

公开话题使用音乐、电影、游戏、颜色、科普的固定词表；敏感、图片、引用及不确定材料不选。拒绝公开会删除相关候选和未提交草稿，不删除已发布空间、QQ 聊天或正常记忆。已经提交的外部请求无法靠撤回候选取消。

## 上线核对

核对实际加载版本、余额状态版本 2、日记时间窗、旧排程终态、独立的摘要与通知许可。排名初始为空是正常情况，不应伪造历史补齐。真实 QQ、空间与付费模型验证按用户授权执行。

## 回滚

先停止后台任务，不能让两套版本同时跑。

- 空间新列是附加列，旧代码可以读取。保留所有任务状态与保存时间，不清表、不重置未知或执行中记录。回退后全天随机规则适用于以后新建的任务。
- 社交新增表可保留，旧代码会忽略；不恢复更旧的完整 `preferences.db`，避免丢失用户最新拒绝。
- 余额旧版不能加载版本 2。若升级后没有发送或尝试发送新通知，可核对后恢复一致的升级前备份。已有新通知或未知结果时，不能直接恢复 `state.v1.bak`，否则可能重复通知。
- 已有新通知时，先停用余额插件，保留最新版本 2 状态完成其他代码回滚。待真实余额恢复到至少一元且当前轮次完全结束（`cycle` 为 `null`），复制最新状态到独立文件，将副本 `version` 改为 1，保留 `last_cycle`、`daily_help` 和所有回执，核对后供旧版加载。存在未决发送时继续停用，先核对真实结果；原文件与副本都保留。
