2026-10-30，北京时间。基于 `cbd32673f13972a451848596463a365638ad1cc0`，按用户“开始，并且减少一些测试”的要求实施。本轮修改通用处理机制，沿用草稿 PR [#2](https://github.com/chentao-git-1/dafeiyu-qq/pull/2)；没有变更生产插件或配置，没有推广 active 新路径。

**本轮相关检查通过，整体自然度和上线验收仍未完成。** 数值见 [cognition-repair-verification.json](cognition-repair-verification.json)。上一候选的 286 项回归、384 轮回放及服务器核验属于 [此前实施记录](COGNITION_IMPLEMENTATION.md)，不能写成本轮最终代码重跑全套的结果。

## 原因与改动

旧 384 轮候选中有 31 轮失败提示。复查保留的原始输出发现，这 31 轮均在结构或字段阶段失败，尚未进入最终语义核对；其中 18 轮带有额外尾部内容，但不都能安全恢复。

- `generation.py` 只恢复完整对象后的多余闭合符，或完全相同的重复对象，保留原文字和字段值。不同草稿、尾部工具片段、缺失必需字段、重复键或截断对象仍拒收。重复键以前可能被 JSON 解码器悄悄覆盖，现在明确拒绝。
- 无效的语音意图退回中性，缺失/无效的焦点和引用元数据必须经过已有的 enforce 语义核对才能使用。只有明确的无操作隐私对象与空学习列表可做无操作字段归一化，不补猜遗忘目标、来源编号或学习条目。原来的身份、证据、版本和送达检查保留。
- `learning_check.py` 不再接收主模型预填的主体、语态、持续性与类别标签。它从本人原话及同会话的人类上下文独立判断主体、陈述/真实意图/假设/引用、跨轮价值，并提供逐字证据；无解释的编号批准不再有效。仍然只核对已提出的条目，不创造资料或改变归属。
- 进一步明确“跨轮保存”与“永久偏好”的区别：真实计划、进展、完成和取消可以保存到事项结束；仅本轮的说话要求和一次情绪不变成持续规则，假想条件本身不能证明当前已生效的偏好。
- `main.py` 分别记录格式、来源、学习、隐私和语义核对失败的数值类别，不记录原文，减少后续反复调用模型排查的需要。
- 若回复格式失败，但当前人类原话已有合法来源且失败提示实际确认送达，可以提前核对一次现有未完结事项，避免漏掉这轮的状态变化。仅允许已提供的事项编号，逐字证据绑定当前本人原话，仍检查版本与隐私 epoch，不新建事项；同一来源重复回调不会再核对。核对策略要求本人拒绝保存或要求遗忘时返回空更新。该补偿计入原有后台模型账目。

这些处理不按聊天关键词选择回复，也没有为某句失败样本添加特例。

本轮真实模型请求 **合计 32 次，包含上述失败请求**，达到预设上限后停止。对话输入均为合成资料，数据库为独立临时目录；没有真实 QQ 发送、空间发布或生产记忆写入。没有用新一轮数百次回放替代小范围定位。

## 当前边界与下一步

本轮已修复可恢复格式与学习核对的部分通用缺陷，并为漏掉的已有事项状态增加独立补偿。仍有应当拒收的多义/截断输出，真实模型也仍可能漏标或误判。新的局部样本不足以估计长期失败率、自然度胜率或完整召回质量。

保持候选开关和草稿状态。后续优先观察最终状态补偿及真实计划/假设的区分，确认稳定后再安排真人盲评与主人私聊试运行；沿用原方案的至少 3 天、100 个有效回合及 active 关闭/恢复演练。无需继续堆叠全套测试或为单句增加规则。
