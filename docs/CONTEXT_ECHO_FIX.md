# 旧回答与主动消息的重复注入

2026-11-06 **19:31（北京时间）已部署并只读核验通过**。代码 `7d98a78d9fc7a992fcd3d7d81805d0816ba8fdb5` 已推送 main，核心 0.3.3、统一对话 0.7.2、运行时 0.3.6；日常 0.7.2 和临湾人设保持。见 [上线证据](context-echo-deployment-20261106.json) 与 [真实记录副本回放](context-echo-replay-20261106.json)。

实际私聊中，新的问候、当前话题和自我介绍反复回到同一篇旧作品。只读检查发现，运行时把最近三条主动消息作为附注追加到每一条用户输入，随后又随原生历史保存；同一条旧分享因此在多个用户回合中重复出现。另一个入口按字面相似度自动召回成对问答，常见问法会带回一批机器人自己的旧回答，重复占满记忆上下文。

修改输入来源的组织方式：

- 统一对话模式中的主动消息沿用已有送达账本，按真实时间作为一条 assistant 历史接入，不再附在当前用户消息后面。确认发送、联系人和会话范围、遗忘处理保持原约束。
- 旧版本已经保存的重复附注只在模型输入副本中移除。必须匹配这个联系人的实际送达账本、原系统附注格式和原生时间标记，才可移除；用户文字、图片、原 assistant 回复、当前输入和数据库原历史保留。伪造标记、未知来源、混有额外用户文字时保持原样。
- 普通聊天的自动记忆只选长期事实、偏好、事件等独立记录，不自动注入原始成对问答。原生近期历史继续可用；明确回忆工具仍能检索原问答。索引与上下文装配两处采用相同范围，旧排序结果不能把原问答重新带入。

不增加选题或审稿模型，不修改输出措辞，不设置话题禁词，不重置人格或清空聊天。该修复切断重复输入机制，不能仅靠代码检查宣称之后每一句表达都不会重复。

验证使用模拟提供商与捕获的请求，覆盖连续多轮、真正的原生 runner、只修改模型副本、主动消息顺序与去重、图片保留、未知来源、当前原话、明确回忆和既有语义记忆行为。部署前再以线上记录的私有只读副本断网回放，只输出统计，不把聊天原文提交到仓库。
